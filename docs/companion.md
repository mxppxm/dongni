# 对话旁的黄色陪伴角色

对话旁的可动小人和通话中使用同一 Companion 组件的大小图，改用 BoopFace 0.8.0 的 504 号“亮光黄”皮肤。只替换 UI 角色的绘制和动作，不修改 Min（敏）的人格、提示词、记忆、原型参考图、mood 图片、相册或生成规则。原有 `min-atlas.png`、`min-bodies.png` 等素材仍保留，不再由 Companion 使用；消息里的 Mood 贴纸仍使用原图。

`public/companion/boopface/` 保存从官方仓库提交 `ceb0580b5f8ee8b93f206920baba5265d7d7d482` 原样复制的 Web 入口及 src，共 35 个运行时/许可文件，另附来源说明 NOTICE.md。MIT LICENSE 随代码保留；BoopFace 名称及原始角色归 CX ArtLab，不声明为懂你的原创形象。

浏览器挂载后加载本地 ES Module，多处角色共用一次加载。SSR 不访问 HTMLElement 或 customElements。皮肤绘制器继续使用上游按需加载，不请求外部 CDN 或新增模型。加载过程中使用黄色占位，失败时显示“角色加载失败”。

## 业务状态

`lib/companion-state.ts` 将现有消息状态和任务栏同一轮快照转换为角色呈现，不新增任务轮询。优先级：任务要求回答；正在回复或发送；停滞的任务；运行/排队任务；短暂结果反馈；正在输入；待机。

| 来源 | 呈现 |
| --- | --- |
| 后台任务 stage=asking | wary，提示“等你回答” |
| 发送、等待回复 | 循环等待 |
| 流式回复 | affirm，提示“正在回应” |
| 运行/排队 | wave 等待，区分“正在忙”“排队等开工”和多任务数 |
| 任务至少 120 秒无进展 | wary，提示任务没有进展 |
| 观察到回复/任务完成 | 短暂 success；有 mood 时按情绪表达 |
| 回复/任务失败、通话错误 | failure，不再用疑惑代替错误 |
| 输入框有文字且聚焦 | input |
| 空闲 | idle，90 秒无活动后自动休眠 |

刷新载入的已完成历史不触发庆祝。新任务、请求和等待回答优先于短暂结果反馈。状态变化会 reset 上一段动画并取消旧的异步续播，避免旧动作结束后把新状态覆盖成等待。活动期间关闭自动休眠。业务状态变更和键盘互动会唤醒角色。

## 心情与交互

角色接收正在回复的消息的 `mood`，以及完成瞬间的 mood；通过与原有 Mood 贴纸共用的缓存读取 `/api/moods` 元数据。已生成的自定义 mood 依据 preset/fx 适配动作，既不修改 mood 生成也不按聊天文本猜测情绪：

- comfort / hearts：love，表达陪伴。
- cheer / jump / sparks：surprise，表达开心，不把未完成的任务显示成 success。
- wave / hi：affirm，回应招呼。
- draw / scribble：inspect，表达专注；generate_image/create_mood 任务也使用这一表达。
- run / stride：wrap 等待；普通等待使用 spin，工作使用 wave。
- shake：wary；未知 mood 保留正常业务动作。

等待阶段可先播放情绪动作，之后恢复对应的循环等待。确认、失败、输入状态不被 mood 覆盖。通话仍读取现有连接和实际音频状态：接通中等待、倾听时 inspect、她回应时 affirm；BoopFace 没有嘴部，不声称对口型。

聊天旁角色可在整个窗口范围内拖动，松手停留，不回弹到初始位置；为避免与上游局部形变手势冲突，拖动由外层负责，通话中的原有局部互动保持不变。双击或聚焦后按 Enter/空格打招呼，方向键每次调整 20px，随后恢复等待。遵循系统减少动态效果偏好，上游运行时处理页面隐藏、离屏和休眠暂停。

角色不再显示下方或旁边的状态文案，状态保留在无障碍描述中。桌面初始位置和窄屏布局沿用现有区域；窄屏角色宽 56px，初始收进输入框上方。拖动边界距离窗口四边各 12px，窗口缩放时自动将角色移回可见范围。记忆、相册、本事面板或通话打开时，聊天旁的角色继续按原有条件隐藏。
